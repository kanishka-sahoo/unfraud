# Training features are produced by replaying the stream through the Go feature engine

There is exactly one feature implementation. Training data is generated by an Accuracy Run that writes the Go engine's features to Parquet, and Python only trains on that file. This rules out training/serving skew by construction, at the cost of not being able to prototype features in pandas.

## Considered Options

- Python features for training plus a Go port for serving: the usual source of silent skew in these projects.
- A feature-store product (for example Feast): heavy, and it still needs a streaming implementation.
